The Revibe Hackathon

In groups of about three, you rebuild one paper’s system with a coding agent, from the paper alone. You grade the build against the rubric on this page (version 1), the agent fixes what you found, and you grade again (version 2). At 11:00 each table compares its revibes and picks one to remix. The method follows the “Revibing Code from Papers” paper.

Today’s Papers

Each table picks one paper, and every group at the table revibes it. The links are for you, not your agent: the agent works from the paper alone. Images: Figure 1 of each paper, by its authors.

Before You Start

Who You Are

Fill this in once. The prompts, commands and rubric on this page adjust to your paper and group. Everyone in your group uses the same table and group.

What You Need

  • Claude Code or Codex, installed and signed in.
  • Python 3, git and Node.js.
  • No API key. When the rebuilt system calls a language model, the call goes through your agent and your plan.
  • No plan? Ask an organizer for a Codex credit link ($100, one per person). Open it while signed in to the ChatGPT account you will use, then run codex and sign in with that account. Credits expire 30 days after you redeem them. Please don’t share links.

Get Ready you

  • Start your agent. One person opens a terminal in the repository folder and runs claude or codex. That laptop runs the agent and the system you build.
  • Take notes on FigJam as you go: write down what happens on your table’s frame, one idea per sticky: questions challenges ideas decisions. They feed the table share at 11:00 and the afternoon discussions.

Open the FigJam board

1

Build from the Paper agent

Send this prompt to your agent, unchanged. It comes from the “Revibing Code from Papers” method: the agent reads the paper, lists the system’s features and interface, builds it (a web app if it can), and writes a README on how to start it.

Send to your agent
We are revibing [SystemName].

You will be implementing the [SystemName] system. This is based on a paper. The paper's content is split into markdown files and images in the 'paper' directory.
Proceed in the following steps:
(1) Analyze the features of the system and user interface (use the paper content and images)
(2) Create a new implementation of the system that supports all the described features. Create this as a web app if you can, but you can use an alternative approach if the design calls for it (e.g., a Python backend). You may select alternative libraries or languages for implementation that deviate from those used in the paper.
(3) When you are done, create a DEVELOPER.md that provides a detailed walkthrough of what a developer needs to know and install to run the system. Also, create a README.md that describes how to launch and use the system.
Additional instructions:
* You may ask questions if something is unclear but provide alternative choices.
* If you need access to an API key, you can check for an available .env file. If the key does not exist, you can leave instructions in the .env file. Notify me, and I will fill it out.
* It is ok to use roughly equivalent APIs (e.g., if the API calls for using a OpenAI model and you only have access to Gemini, you can use that)
  • The agent asks a question? Answer from the paper, or pick the option it suggests.
  • While the build runs, read the rubric so you know what you will test.
2

Debug Until It Launches you, then agent

Start the system as revibes/<paper>/app/README.md says. If you see errors, paste them to your agent and ask it to fix them. Repeat until the system runs.

3

Feature Check: Version 1 agent

Ask your agent to check what it built against the paper and add what is missing. You can also try the system yourself and tell the agent which features are missing.

Then: restart the system (back to step 2 if it fails). The agent’s note on what it built is in revibes/<paper>/changes/v1.md.

4

Grade Version 1 you

Grade in the rubric below.

  • Grade together. Each of you can open this page on your own laptop with the same table and group. Every grade saves for the whole group.
  • Split the work. One person uses the system, the others read the tests and click the grades. A test you cannot try is a failure.
  • Write what you saw for anything partial or failed. The agent fixes from those notes in step 5.
5

Fix from Grades: Version 2 agent

In the rubric, click Copy for the agent and paste it to your agent. The copy already asks it to fix what you graded partial or failure, using your notes. The first copy also keeps your version 1 score for your table.

Then: restart the system and check that it starts. This is version 2.

6

Update Your Grades you

Try version 2 and change the grades that changed, starting with the tests that were partial or failed. Your table’s scores show both your first grades and where you are now.

Your Rubric

An agent wrote these tests from the paper, and each one shows the section or figure it checks. Every group at your table grades the same tests. Keep one set of grades and update it after each fix.

Your Table

Share Your Revibe

When you are done, push your revibe as a branch named after your paper and group.

git push origin HEAD:revibe/<paper>-<group>

This pushes the code, the agent’s notes and your grades. Push again whenever you add more.

After the Revibe: Remixing

Your table remixes the revibe it picked: change it on purpose to test an idea the paper did not.

The whole table works on one remix branch, remix/<paper>-<table>.

  1. One person starts the branch from the revibe your table picked: put in that revibe’s group number.
git fetch origin revibe/<paper>-<table>-group<picked group>
git checkout -b remix/<paper>-<table> FETCH_HEAD
git push origin remix/<paper>-<table>
  1. Everyone else joins it.
git fetch origin remix/<paper>-<table>
git checkout -b remix/<paper>-<table> FETCH_HEAD
  1. Tell your agent what you are changing and what question it explores. It records this in revibes/<paper>/remixes.md. Agree at the table who changes which part, so you do not edit the same files.
  2. Share your changes whenever something works. The first line takes in your table’s latest changes first.
git pull --rebase origin remix/<paper>-<table>
git push origin remix/<paper>-<table>
